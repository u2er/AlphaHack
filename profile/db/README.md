# Индексация приложений в PostgreSQL

Данные приложения 1 и фрагменты документов приложения 2 хранятся в схеме `profile_data`. Для семантического поиска нужен PostgreSQL с расширением `pgvector` и локальная модель `models/multilingual-e5-large`. Векторы сохраняются в `profile_data.chunks.embedding`; после загрузки создаётся индекс HNSW. Импорт выполняется отдельно от профиля и GUI.

## Подключение

Локальный сервер из репозитория:

```bash
docker compose -f deploy/postgres/compose.yaml up -d --wait
venv/bin/python -m pip install -r requirements.txt
```

В `.env` или окружении задайте строку подключения:

```dotenv
PROFILE_DATABASE_URL=postgresql://alfa:alfa@127.0.0.1:5434/alfa_profile
```

Для другого PostgreSQL используйте его DSN и заранее обеспечьте доступность расширения `pgvector`. Команде можно передать DSN отдельно через `--dsn`.

## Контракт парсера документов

В `parser` нужно добавить Python-модуль с вызываемой функцией, например `parser/custom.py` с `parse_document(path: Path)`. Индексатор передаёт ей путь к одному PDF из `приложение 2`. Способ чтения PDF, OCR, кэширование и настройки парсера находятся внутри этого модуля; `profile.db.prepare` их не задаёт.

Функция должна вернуть словарь такого вида:

```python
{
    'date_hint': '2026-09-11',  # дата документа либо 'unknown'
    'pages': [
        {'page': 1, 'text': 'Полный текст первой страницы', 'extraction': 'имя-парсера'},
        {'page': 2, 'text': 'Полный текст второй страницы', 'extraction': 'имя-парсера'},
    ],
}
```

`pages` — непустой список страниц в исходном порядке, пронумерованных подряд с 1. `text` каждой страницы должен быть непустой строкой. `extraction` — непустое название способа извлечения; оно сохраняется как происхождение текста. `date_hint` — непустая строка с датой или `unknown`, если дату установить нельзя. Неверный результат останавливает импорт, а транзакция PostgreSQL откатывается. Хэш документа и имя файла индексатор получает самостоятельно.

Импорт приложения 1 уже использует `parser/csv.py`: он читает три исходные таблицы CSV. Парсер PDF в репозитории не поставляется.

## Запуск индексации

Когда функция парсера готова, укажите её как `parser.module:function`:

```bash
venv/bin/python -m profile.db.prepare --parser parser.custom:parse_document
```

Команда загружает CSV из `формулировка и данные хакатона/приложение 1` и все PDF из `формулировка и данные хакатона/приложение 2`. Для другого набора файлов используйте `--source /path/to/folder`; внутри должны быть папки `приложение 1` и `приложение 2` с теми же CSV-именами и PDF соответственно.

Если схема `profile_data` уже заполнена, команда остановится. Для явной пересборки добавьте `--replace`: данные схемы заменяются в одной транзакции, а при ошибке старые данные сохраняются.

После импорта проверьте базу:

```bash
docker compose -f deploy/postgres/compose.yaml exec postgres \
  psql -U alfa -d alfa_profile -c 'SELECT count(*) FROM profile_data.companies; SELECT count(*) FROM profile_data.chunks;'
```

Справочники полей можно обновить без переиндексации: `venv/bin/python -m profile.db.field_labels`. Смена модели или парсера требует новой индексации с `--replace`. Профиль и GUI только читают подготовленную базу.
