# Интерфейс «Альфа-Бизнес»

Прототип интернет-банка Альфа-Бизнес для бизнес-аналитики. Работает в браузере на стандартном `http.server` Python.

- **Главная** — заметная точка входа в бизнес‑аналитику с главными событиями дня и карточки профиля.
- **Бизнес‑аналитика** — лента выбранной компании (`GET /profiles/{id}/feed` EventGraph): важность, риск или возможность, горизонт. В карточке события источники разведены: `AI` — интерпретация и что можно сделать; `Альфа‑Банк` — близкие фрагменты отчётов аналитиков банка (`profile_data`), старые помечены как исторические; `Источник` — первоисточник и событие в графе.
- **ИИ-функции аналитики** — фильтр важности по шкале 1–5, сохраняемая сводка по текущим фильтрам и 15 самым свежим новостям, обсуждение отдельной новости с доступом агента к графу и история чатов. Во вкладке профиля можно запросить черновик точечных правок, посмотреть подсвеченный построчный diff и сохранить изменения только после подтверждения.
- **Бизнес‑аналитика → Источники** — источники выбранной компании (галочки) и управление коннекторами: состояние, последний запуск и ошибка, «Запустить», «Проба», «Пауза»/«Возобновить», «Сбросить курсор», история запусков.
- **Граф событий** — граф EventGraph на canvas: свежие события с соседями, поиск по имени и по смыслу (Enter), фильтр по типам, клик — подробности и публикации узла, двойной клик — раскрыть связи. В правой панели ИИ-агент отвечает по всему графу: находит актуальные события, противоречия, узлы с наибольшим числом связанных событий и анализирует взаимосвязи; при выборе узла панель показывает его подробности.
- **Профиль компании** — страницы профиля выбранной компании: основная (её аналитик видит всегда) и остальные по оглавлению.
- **Добавить компанию** — чат (`profile/onboarding.py`, `gui/onboarding.js`):
  1. анкета (деятельность, масштаб, география и ВЭД, контрагенты, что влияет на бизнес, роль) и документы компании — годовой отчёт или бухотчётность, презентация, каталог или прайс, список контрагентов, кредитный портфель, стратегия; PDF (в том числе сканы — OCR docling), Word, Excel, PowerPoint, HTML, текст, CSV, картинки; до 30 МБ, до 10 файлов;
  2. агент читает файлы и задаёт до пяти вопросов — один вариант, несколько вариантов или свободный ответ; в чате видно, что он делает;
  3. агент собирает страницы профиля: основная, аналитические, полный текст файлов, данные набора банка, анкета и ответы; у страниц — ссылки на источники;
  4. пользователь листает страницы, правит любую вручную (у основной — счётчик лимита) и подтверждает. Профиль сразу записывается в EventGraph API и экспортируется в `PROFILES_DIR`; он появляется в переключателе компаний без ожидания следующего цикла воркера;
  5. интерфейс предлагает выбрать источники новостей (коннекторы EventGraph) — они записываются в профиль (`news_sources`).

  Тем наблюдения в профиле нет: аналитик оценивает новости по самому профилю, аналитика банка приходит к нему через граф (коннектор `alfa_analytics`).

- **Вход** — интерфейс открыт только по ключу доступа (`GUI_ACCESS_KEY`; пусто — при первом старте создаётся случайный ключ из 40 символов, он пишется в `DATA_DIR/gui-access-key` и в лог). После входа — HttpOnly-кука на 30 дней; новый ключ выводит всех.
- **Настройки (шестерёнка справа вверху)** — LLM для агентов, чатов и мастера профиля: провайдер, адрес API, модель, ключ, картинки, доп. параметры, потолок токенов, таймаут. Значения по умолчанию — из `.env` (нет в `.env` — пусто); изменённые хранятся в `DATA_DIR/llm-settings.json` (`utils/llm_overrides.py`) и подхватываются api, воркером и GUI без перезапуска. Ключ API браузеру не отдаётся — только его последние символы.

Ленту GUI берёт у EventGraph сам: `EVENTGRAPH_URL` (в compose — `http://api:8000`) и `API_KEY`; браузер ключа не видит (`gui/insights.py`). Каждый проход чата пишется в `GUI_RUNS_DIR/<id>/`: файлы, `trace.jsonl` (сообщения, запросы и ответы LLM, обращения к базе), `draft.json`, `profile.json`.

## Запуск

В compose интерфейс поднимается вместе с остальным (`eventgraph-profile-gui`, http://127.0.0.1:8765, порт — `PROFILE_GUI_PORT`). Поиск компании в наборе банка требует библиотеки компаний: если её нет, интерфейс при старте сам загружает CSV приложения 1 в `profile_data` (около минуты; пока идёт загрузка, поиск отвечает «загружается»). Вручную — `docker compose run --rm profile-prepare --companies-only`, см. `profile/db/README.md`.

С хоста, из корня репозитория:

```bash
PROFILE_DATABASE_URL=postgresql://eventgraph:eventgraph@127.0.0.1:5433/eventgraph API_KEY=… .venv/bin/python -m gui
```

Проверки:

```bash
.venv/bin/python -m pytest tests/tests_gui tests/tests_profile/test_onboarding.py
```
